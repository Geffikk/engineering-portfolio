Numbers that survive a year

A self-hosted platform that turns regulatory filings into auditable company valuations, tracks a real brokerage portfolio against them, and uses language models only where a language model is actually allowed to be wrong.

What it does

Three things, in the order the data flows

VALUE

Compute from primary sources

Financial statements come from SEC EDGAR XBRL, not from a data vendor and not from a chatbot. Forward FCFF path, derived cost of capital, DCF, EPV and a reverse DCF, with scenarios and a sensitivity grid.

VERIFY

Read the market’s opinion, then check it

Deep research reports come from commercial LLM research products. Every factual claim is then verified against the page it cited. A report whose citations do not hold up is stored and scored as refused, never quietly dropped.

TRACK

Follow a real portfolio

Positions and tax lots are imported read-only from a broker, reconstructed from transactions, and linked to the valuations, so a holding can be read against its own fair value band.

The system never places a trade. That is a design decision, not a missing feature. The whole point is a decision-support tool whose numbers can be defended, and an execution path would be a second class of risk with none of the same guarantees.

Architecture

One host, nothing exposed

Nothing is published

The API is not reachable from the internet at all. Host administration is over WireGuard, the machine sits behind NAT, and the public hostname is a tunnel CNAME, so there is no origin IP to find.

The browser is a credential

CDP has no authentication by design and can read every cookie in the profile, so the debug port is never published and the remote desktop is bound to loopback.

No CI runner, no registry

The orchestrator polls the repository, builds the images on the target machine and recreates what changed. A deploy is a push, and the live commit is readable from the running container.

Async work

A queue built on leases, not locks

1 · ENQUEUE

202, not a wait

A run takes ten to twenty minutes, so it cannot live inside an HTTP request. The API inserts a QUEUED job and returns its id.

2 · CLAIM

Atomic, no broker

A worker claims with a single findOneAndUpdate and receives a lease deadline. No Redis, no Celery, no RabbitMQ.

3 · RENEW

Prove you are alive

A live worker renews the lease on every wait pass. Liveness is asserted continuously rather than assumed from a held lock.

4 · LAPSE

Death is survivable

A worker that dies lets its lease expire and the job returns to the queue with the attempt count raised. SIGTERM hands the job back immediately.

5 · SETTLE

Two kinds of failure

DONE with a result, FAILED with a reason, or ABANDONED after too many attempts. The last is a distinct state so a reader can tell “broke once” from “keeps breaking”.

The queue is Mongo documents, deliberately. A job is a document that survives being consumed, which is what makes “why did that one fail three days ago” answerable. A broker would add a container, a connection, a failure mode and a second place the truth lives, to buy throughput that a few dozen jobs a day will never need. The trade-off is written into the code so the next person can reverse it on evidence rather than taste.

The hardest problem

Making a number provable a year later

A valuation that cannot be reproduced is an opinion with a timestamp. The engineering question is not “is this number right”, which nobody can answer, but “is this the number the stored inputs produce”, which is decidable.

Where a hash lies

Hashing the inputs is the obvious move and it fails in three quiet ways:

  • Key order. The same document serialized twice can hash differently.
  • Decimal spelling. A filer’s trailing zero looks like a changed value.
  • Binary floats. Converting one into a hashed payload is exactly where lost precision becomes invisible.
What I built
  • Canonicalisation that sorts keys at every depth, normalises Decimal spelling, and refuses a binary float in a hashed payload outright rather than converting it.
  • Decimal end to end, with no floats anywhere in a hashed path.
  • A replay that recomputes a stored run from its stored inputs and compares field by field.
Three possible answers
  • The hash no longer matches its payload. The record was altered after the fact.
  • The value moved. The code changed, which is how an engine upgrade gets measured, and which must never happen silently.
  • Nothing. Which is the answer that makes the number on the screen defensible.

Being strict here is what lets everything downstream stay simple: no rounding rules, no tolerance windows, no “close enough” comparisons.

Other problems worth describing

Four bugs that were not what they looked like

SymptomWhat it actually wasThe fix
Three research reports took three sequential runs Threads looked like the answer, but a Playwright sync connection cannot be shared across threads. The browser was never the limit, the connection was. One worker process per source, pinned so a worker never takes another source’s job. Three sites run concurrently while the guarantee that mattered, at most one conversation per site, still holds.
Reports scored 1 to 5 out of 12 on citation checks The tempting fix was to lower the bar, which would have hidden the bug. The checker read five of a page’s twenty sources, demanded both ends of a hedged range, refused the same figure written in millions instead of billions, and asked whether one three-sentence window carried a claim stating three separate facts. Fix the checker, not the threshold. Same provider, same company, 11 of 12. The card now shows the divisor, so a reader can tell 12 of 12 from 5 of 12 without knowing a threshold exists.
A company with two finished reports showed a dash and “no verified number yet” One root cause in two places. The guard preventing cross-currency averaging compared raw strings, so $80 and USD 65 looked like two currencies. Separately the chart keyed points by exact timestamp although its own comment claimed same-day reports were averaged. Normalise currency to an ISO code at extraction and at read time, so documents already stored were corrected with no migration, and group the chart by calendar day through the same functions that compute the card. Chart and card can no longer disagree.
The whole analysis surface answered 403 for most of every week The backend token lifetime and the web session lifetime had drifted six days apart. The cause was ${VAR:-default} in the compose file with an explicit value set in the orchestrator’s stack environment: the explicit value wins, silently, so changing the default in version control did nothing. Both values are literals in the compose file, the web session length derives from the backend’s, and the reason is a comment above the line. Non-secret configuration does not belong somewhere only one person can read.
The listing page took 2.70s 2.57s of it was 42 sequential upstream price calls sitting inside the request path. A stale-while-revalidate cache: 3s cold, 0.19s warm, including after the TTL expires, because the stale value is returned while the refresh runs behind it. An empty upstream response is never cached, because a slow reload beats showing “no companies” for fifteen minutes.
Failure handling

Refusing is a first-class outcome

The system is a single host talking to sources that rate-limit, log out, move their selectors and go down. Most of the engineering is in what happens then.

FailureBehaviour
Worker dies mid-jobLease expires, job returns to the queue with attempts + 1
Worker receives SIGTERMJob is handed back immediately, not left claimed
Job fails repeatedlyCapped attempts, then ABANDONED, a distinct state from FAILED
Browser container missingJob is deferred, not failed, up to a generous cap; past that it is a real outage someone must see
Nightly sweep hits a bad entityRecorded, the pass continues, non-zero exit code at the end
Sweep and a manual run collideBoth take the same Mongo advisory lock with a TTL; the second reports “already running”
Database briefly unreachable at bootIndex bootstrap is guarded, the app starts, the client is lazy
Upstream returns emptyNever cached
Blob archive growthContent-addressed, refcounted, retention sweep, hard storage cap that refuses explicitly rather than growing without bound
Missing encryption keyEndpoints that would persist a broker identifier refuse loudly instead of writing plaintext
Data too poor to valueExplicit refusal with a stated reason, never an invented number

The last two are the theme. A tool whose job is to produce a number is most dangerous when it produces one it should not have, so refusal has its own vocabulary and its own screens.

Security

One session model, verified twice

No published ports

The sole ingress is an outbound Cloudflare Tunnel behind a WAF geoblock and Zero Trust Access. API, database and the browser debug port are unreachable from the internet.

Broker identifiers encrypted at rest

Fernet, keyed from the environment. Because Fernet ciphertexts are salted and therefore useless as a lookup key, find-or-create uses a keyed HMAC-SHA256 of the same value.

Logs are scrubbed

A redaction filter is installed on the root logger and the application logger, so an identifier or token cannot reach a log line even from code that never thought about it.

Sessions verified twice

The backend issues a JWT; Next.js middleware verifies it before a page renders and the API verifies it again on every call. Google OAuth logins bridge into the same cookie.

The broker connection is read-only

Read-only by token scope, and there is no order path anywhere in the codebase.

Secrets in the orchestrator

Secrets live in the stack environment, never in the repository. Non-secret configuration deliberately does live in the repository, so its history is readable.

Operations

A deploy is a push

The orchestrator polls the repository, builds the images on the server and recreates the changed services. Rollback is a revert and another poll.

Scheduled work runs from host cron as a module inside the running backend container, 2.5 hours after the regulator publishes its daily index. No HTTP and no long-lived admin token in a file on disk. The sweep takes the same advisory lock the UI button takes, prints a JSON report of examined / due / regenerated, and exits non-zero if any entity failed, so a scheduler watching exit codes notices.

Monitoring today is Docker healthchecks and restart policies, the orchestrator’s container view, the sweep’s exit code and log, and a structured in-app log viewer with a request id on every entry, so a reported problem can be traced to a request without shell access.

The monitoring gap, stated honestly: there is no metrics stack and no paging. For a single-user internal tool that is a deliberate cost decision rather than an oversight, and it is the first thing I would add if it carried anyone else’s money.

Engineering practices

Claims that were measured, not felt

2,568 backend tests across 108 files. The clock, the HTTP transport and the database are injected everywhere, so the suite runs offline and never waits on a real rate limiter. Bugs ship regression-first: the currency fix shipped with six new tests, one class of which is named after the invariant it protects.

Type checking and lint gate the frontend, compared against a stashed baseline so “no new warnings” is a measured claim rather than an impression. Non-obvious constants carry the measurement that produced them and the date it was taken. The whole UI is bilingual, about 1,360 translation keys, with label maps holding keys rather than resolved strings so module-level constants cannot capture the wrong language.

Anonymized public documentation. Credentials, broker account data, investment strategy, real positions and private endpoints are deliberately excluded. The source repository is private. An anonymized example of the product output is available as a sample valuation report.
