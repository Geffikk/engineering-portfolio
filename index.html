How I work

Four habits both systems share

Measure before optimising

A stage-latency waterfall showed internal coordination was under 30ms and the venue round-trip was everything, which killed a planned code optimisation. A profile showed 2.57 of 2.70 seconds was 42 sequential upstream calls, which produced a real one.

Absence is a first-class alert

My worst incidents were silences, not crashes: production dead for nine days with every alert green, a pipeline producing zero jobs for 33 days with nothing red. Both systems now alert on things not happening, and one sends a daily heartbeat so silence itself can be trusted.

Refusing beats guessing

Stale prices, unreachable venues, unknown outcomes and data too poor to value all stop the work with a named reason. A refused result is stored, shown and counted, because a scoreboard showing only what passed is the same error as an investment record that keeps the winners.

Every number comes from a measurement

One system derives all money from measured fills, never from the plan, after learning that the difference reported profitable trades as losses. The other hashes the exact inputs behind every valuation so a stored number can be replayed and proven.
